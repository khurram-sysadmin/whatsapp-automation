# Automatic customer-owned WASender setup — 2026-10-04

Approved flow: customer signs up/pays WASender, links WhatsApp there, temporarily enters a Personal Access Token, selects a connected number, and approves configuration. New WhatsApp Accounts → Add WhatsApp Account uses this flow; old connections retain their existing settings and manual setup guides. No provider subscriptions, purchases or message sends are performed by setup.

Implementation: src/saas/AutomaticConnection.tsx and public/connect/{wasender.php,setup-core.php}. The existing 31-action n8n/Supabase contract is reused through bootstrap, sessionList, sessionCreate and sessionConnect. No new n8n workflow, direct browser Supabase secret or schema migration. PHP uses the verified user JWT; the provider PAT stays out of n8n. Customer-selected IDs are fetched under that PAT again; keys, phone identity and secret come from provider responses, not browser claims. Existing backend independently verifies the session key and stores its secrets in Vault.

Security: server checks auth-derived active-company owner/admin membership BEFORE using the PAT. Only fixed HTTPS upstream hosts and numeric session IDs are used; TLS verification and redirects-disabled apply. Setup changes webhook fields only. Existing external webhooks require an explicit checkbox. Existing EightBit branded/n8n webhooks are not transferred or reconfigured automatically; contact support for migration/recovery. This avoids silently moving a number between companies. Responses contain allowlisted metadata only. PAT is volatile in the mounted setup, cleared on successful save/cancel and after ten idle minutes, never placed in storage or idempotency digests. Requests abort on unmount; changing company remounts the component. PHP writes no credentials or raw bodies to disk/logs and does not return upstream errors; no broad CORS. JSON, Origin, bearer format and bounded request/response validation plus 30/minute per-address rate limiting are enabled. Rate file contains hashed addresses and expiring counters only, in server temporary storage outside the document root, mode 0600. Hosting/WAF/APM must not capture authorization or request bodies; TLS and other protection cannot be guaranteed without hosted inspection.

Only the chosen session key and webhook secret are stored encrypted by the existing backend. Provider PUT response must confirm URL, enablement, every required event and a security secret. Setup probes the branded relay before creating/changing provider configuration, so a missing relay fails closed. Signed callback is still necessary before delivery/inbox readiness can be confirmed. Subscription billing stays with the customer's provider account. No account PAT is retained for future management; reconnect/setup changes require a new temporary PAT.

Failure recovery: an upstream failure is never presented as Connected. Session creation uses a stable request ID per selected number/name. Provider mutation and database commit are separate transactions; a failure after provider update can leave an unconfigured EightBit record/provider webhook requiring operator reconciliation. Do not repeatedly create new connections or overwrite webhooks to force success. Support must inspect the existing local session and provider webhook and finish/restore using authorized credentials. Unknown message outcomes remain untouched. Automatic retries or deletion of provider sessions are not implemented.

Validation: PHP 8.5.11 portable runtime downloaded from the official PHP site with its published SHA256 checked. PHP lint passed for setup endpoint/core and relay. Injected-transport tests verify viewer/member rejection, wrong-company denial, secret-free metadata/results, webhook confirmation, no automatic EightBit transfer, provider failures and successful configuration. These tests make no external calls. Live local HTTP checks confirm method 405, wrong Origin 403 and missing bearer 401. Production/TypeScript build, v2 frontend, runtime, lifecycle passed; targeted new-component lint passed. Earlier v2 workflow tests passed with unchanged workflow sources. The UI was browser reviewed with a fixture containing no credentials, then fixture removed. Bundle size advisory remains approximately 508 KB.
